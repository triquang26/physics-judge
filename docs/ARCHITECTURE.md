# Architecture

kinescore turns generated robot video into physics-violation counts. One learned
component (a keypoint reader), five analytic detectors, and a registry that
decides which reader is allowed to score which video.

```
video frames ──▶ frozen DINOv3 ──▶ KeypointHead ──▶ P (B,T,K,3) ──▶ detectors ──▶ report
                 (backbones/)      (heads/)         metres,          (violations/)
                                                    base frame
```

## Identities

Two ids run through every stage.

| id | shape | one per | example |
|---|---|---|---|
| reader | `<robot>.<view_id>` | trained head | `franka_panda.mv3_row` |
| cell | `<embodiment>.<view_id>.<model>` | scored unit | `single_arm.mv3_row.ctrlworld` |

A cell names the reader it reads through. Several cells can share one reader —
the same robot seen in the same packing, generated by different models. `method`
(`dense` / `augment` / `worldcache`) and `split` (`makovian` / `non_makovian`)
are sub-partitions *inside* a cell, not separate cells.

Both are declared in `configs/*.yaml` and resolved by `registry/cells.py`. A
reader carries a `status` string; a non-empty status blocks the reader and every
cell that names it, so a missing corpus fails at registry-resolution time rather
than halfway through a GPU job.

## Modules

| package | responsibility |
|---|---|
| `adapters/` | corpus → `RawEpisode` (videos + joint arrays + scene key). One module per source layout. |
| `registry/` | `configs/*.yaml` → readers, cells, view geometry (`views.py`), canonical train tree (`materialize.py`), run manifests (`provenance.py`). |
| `backbones/` | frozen DINOv3 ViT feature extraction, patch pooling, per-panel encoding. |
| `heads/` | `KeypointHead`: pooled patch tokens → `3K` outputs, spatial attention + temporal transformer. |
| `readers/` | `KeypointReader` (backbone + head → `Readout`), checkpoint save/load with cell-identity checks. |
| `robots/` | per-robot `RobotSpec`: joint names, forward kinematics, keypoint links, rigid bone pairs, joint limits. |
| `training/` | token cache I/O, scene-disjoint splits, `KeypointTrainer`. |
| `violations/` | the five detectors and the percentile scorer. |
| `core/` | contracts shared by all of the above: `ClipSpec`/`ViewLayout`, `ClipContext`, `Readout`/`PoseReader`, `RobotSpec` base. |
| `video/` | ffprobe metadata and frame decoding. |
| `cli/` | one `cmd_*.py` per subcommand, auto-discovered by `cli/main.py`. |

`cli/main.py` imports every `cli/cmd_*.py`, requires `NAME`/`HELP`/
`add_arguments`/`run`, and registers it. There is no second list to keep in
step.

## The learned part is exactly one model

`KeypointReader` is the only trained component. Everything downstream of `P` is
closed-form geometry, so the benchmark's verdict cannot drift when a detector is
re-run, and a detector cannot be tuned to favour a generator. The reader's job is
narrow — read where the arm is — and its error is reported in millimetres against
forward kinematics, so its competence is auditable independently of any score.

## Backbone

`FeatureBackbone` (`backbones/dino.py`) wraps a Hugging Face DINOv3 ViT
(`dinov3_vitl16` by default, `embed_dim=1024`, patch 16, 4 register tokens). It

1. crops the packed frame into per-view panels using `ViewLayout`,
2. resizes each panel to `dino_input`, normalises, runs the ViT,
3. strips CLS + register tokens, average-pools patches by `patch_pool`,
4. returns `(N, V, P, D)` in fp16.

It runs under `torch.no_grad()` and is never trained. `backbones/default.py`
holds the single `BACKBONE_CFG` every stage builds from, so the cache, the
trainer and the scorer cannot disagree about what produced a token.

## Head

`KeypointHead` (`heads/keypoint.py`) takes `(B, T, V*P, D)` pooled tokens and
emits `(B, T, K, 3)` metres in the robot-base frame:

- a learned query set attends over the patch tokens of each frame,
- a temporal transformer (`n_temporal_layers=4`, `t_max=64`) mixes across frames
  when `use_context=True`, and is bypassed frame-by-frame when it is not,
- a linear map produces `3K` outputs.

`use_context` is a `forward()` argument, not a stored flag: the same weights can
be read with or without temporal context.

## Checkpoints

`readers/checkpoint.py` stores `{"head": state_dict, "n_out": 3K, "embed_dim": D,
"cfg": {...}, "meta": {...}}`. `cfg` records `robot`, `view_id`, `n_views`,
`packing` and the head architecture. `load_reader` takes a `ReaderExpectation`
and refuses a checkpoint whose `cfg` disagrees, so a three-panel head cannot be
handed two panels and silently produce nonsense. A tensor the head needs and the
file lacks is fatal; a tensor the file has and the head does not declare is
dropped.

## Detector interface

Each detector implements `fit` (optional), `per_frame(ctx) -> (T,)`,
`calibrate(scores, pct, floor)` and `report(ctx)`. `ViolationScorer` pools
per-frame scores over real clips, sets each threshold at a percentile of real
motion, and then scores generated clips into per-type reports with frame
intervals. See [METRICS.md](METRICS.md).
